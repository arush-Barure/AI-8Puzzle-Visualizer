03 / UNDER THE HOOD

Uniform Cost Search, explained.

How it works

A state is a permutation of eight numbered tiles and a blank on a 3 × 3 board. A legal action swaps the blank with a horizontal or vertical neighbor.

  1. Insert the initial state into a minimum priority queue at cost 0.
  2. Remove the state with smallest cumulative cost g(n).
  3. Test for the goal only after removal from the queue.
  4. Generate legal successors, each with cost g(n) + 1.
  5. Keep a successor only when it improves its best known cost.
  6. Follow parent pointers from the goal to reconstruct the path.

Why it finds the best path

UCS settles the cheapest unsettled path first. Positive move costs ensure a more expensive route cannot later make a settled state cheaper. With unit costs, the optimal cost equals the fewest moves, and UCS expands the same depth layers as BFS.

Strengths & limitations

Complete and optimal on this finite, positive-cost state graph. No heuristic is needed. The trade-off is substantial memory and many expansions because it has no direction toward the goal.

For the finite graph, a binary heap gives O((V + E) log V) time and O(V + E) storage in the general lazy-entry implementation. Only 9!/2 = 181,440 states are reachable from any given 3 × 3 goal.

Heuristics: context only

Misplaced tiles: count nonblank tiles outside their goal positions.

Manhattan distance: sum each nonblank tile’s horizontal and vertical distance from its goal position.

These guide GBFS and A*. UCS does not use either: f(n) = g(n). They are explained here for the assignment discussion, not used by the solver.

Implementation notes

Stable binary min-heap, visited-state filtering, arbitrary goal parity checking, and asynchronous playback. Memory is a rough model of 160 bytes per stored record/reference unit, not a browser heap measurement.
